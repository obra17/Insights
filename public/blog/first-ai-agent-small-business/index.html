Your first AI agent: one job, done well.

By the Obra Insights team · October 17, 2026

Most small businesses don't need an "autonomous AI workforce." They need one tedious job taken off someone's plate, done reliably, without the agent emailing a customer something strange at 2 a.m. That's a very achievable goal. Here's how to get there.

1. Pick one job, not a department

The best first agent handles work that is:

  • Repetitive: it happens daily or weekly, in roughly the same shape.
  • Text-heavy: reading, sorting, summarizing, or drafting.
  • Low-risk if it's wrong: a person reviews the output before it matters.
  • Easy to check: you can tell in seconds whether the result is good.

Good first jobs include triaging an inbox and drafting replies, researching leads and drafting first-touch messages, turning one video or podcast into posts and a newsletter, and summarizing support tickets into a weekly report. Bad first jobs include anything that moves money, signs contracts, or talks to customers without review.

2. Write the job down like you'd train a new hire

Before touching any tool, write a one-page brief:

  • Trigger: what starts the work (a new email, a new row in a sheet, 8 a.m. every weekday).
  • Inputs: what the agent can see.
  • Steps: how a good employee does it today, including the judgment calls.
  • Output: exactly what "done" looks like, and where it goes (a draft, a label, a row, a Slack message to you).
  • Never: the things it must not do.

If you can't write this page, the agent won't be able to follow it either. This document becomes the agent's instructions.

3. Choose the simplest tool that works

You don't need to write code for a first agent. Roughly in order of effort:

  • Built-in assistants in tools you already use (your email, CRM, or helpdesk) for simple summarize-and-draft jobs.
  • Automation platforms like Zapier, Make, or n8n, which connect a trigger, an AI step, and an action with no code.
  • Agent frameworks or custom code when the job needs several tools, memory, or branching logic.

Whatever you choose, run it on accounts your business owns, with the model API billed to you. You want to keep the agent if you part ways with whoever built it.

4. Give it the least access it needs

This is where most of the risk lives. Give the agent read access and the ability to create drafts, labels, or notes, not to send, delete, or pay. Use a dedicated account or API key for the agent so you can see what it did and revoke access in one click. Add the "send" permission later, one category at a time, once you trust it.

5. Keep a human approval step

For anything customer-facing, the agent drafts and a person approves. In practice that's a draft sitting in your email, a message in Slack with Approve and Edit buttons, or a row in a sheet waiting for a checkmark. It sounds slow, but reviewing a good draft takes seconds, and the time saved is still most of the job.

6. Test with real examples before going live

Collect 20 to 30 real past examples (emails, leads, transcripts) including a few awkward ones. Run the agent on all of them and grade each result: right, fixable, or wrong. Change the instructions and run them again until the "wrong" pile is basically empty. Keep this set. Every time you change a prompt, or the model provider updates its model, rerun it.

7. Run it in shadow mode for a week

Let the agent work on live inputs while you keep doing the job as usual, and compare. You'll find the cases your test set missed. When the agent matches your judgment most of the time and the misses are harmless, switch to approval mode for real.

8. Watch cost, errors, and drift

  • Cost: set a monthly spend limit on the model API. For a low-volume job, usage is often modest, but a loop or a flood of inputs can surprise you.
  • Errors: make failures loud. A silent agent that stopped working a week ago is worse than no agent.
  • Drift: models, APIs, and your business change. Review a sample of the agent's work every week or two, and keep a short runbook so someone else can fix it.

A realistic first month

Week one: pick the job and write the brief. Week two: build it and test on past examples. Week three: shadow mode. Week four: approval mode, with a weekly review. By the end of the month you should know whether it saves real time, and which job to automate next.
