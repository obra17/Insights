From prompt to live URL in a weekend.

By Matt Keller · October 16, 2026

AI tools have made building the first version of an app almost free. Launching it is a different story. Most vibe-coded projects stall in the gap between "it works on my screen" and "strangers are using it." This guide closes that gap with a plan you can finish in a weekend.

Friday night: shrink the idea

The fastest way to never launch is to start with ten features. Write one sentence: "[Who] can [do one thing] so they [get one result]." For example: "Wedding photographers can turn a client questionnaire into a shot list in one click."

Then list what's needed to deliver that sentence and nothing else. Usually that's a landing page, a sign-up, the one core action, and a way to pay or join a waitlist. Settings pages, dark mode, and team accounts can wait for version two.

Friday night: pick your tool and stack

Choose based on where you are, not what's trending:

  • No code experience: Lovable, Bolt, or v0 for the UI, with Supabase for login and data.
  • Some code experience: Cursor or Claude Code on a standard stack (Next.js or Vite with Supabase) so you can take the code anywhere.
  • Just validating demand: skip the app. A landing page and waitlist will tell you more in a week.

Whatever you pick, connect a GitHub repo from day one. You want to own your code, not rent it from the tool.

Saturday morning: write the prompt like a spec

A good first prompt reads like a one-page brief: who the user is, the one core flow step by step, what data you store, and what the user sees when something goes wrong. Ask the tool to build the core flow first, with fake data, before adding login or payments.

Build in small steps and commit after each one that works. "Add the shot list page" is a good prompt. "Build the whole app" is how you end up with a codebase nobody understands.

Saturday afternoon: add login and data safely

Add authentication once the core flow works. If you're on Supabase, do two things right away:

  • Turn on Row Level Security for every table and add policies so users can only read and write their own rows.
  • Run the two-user test: sign up as two different users and confirm neither can see the other's data.

Keep secret keys on the server. Anything in a VITE_ or NEXT_PUBLIC_ variable is public.

Saturday evening: deploy early

Deploy the moment you have a working core flow, even if it's ugly. Deploying on Sunday night is when people discover missing environment variables, broken auth redirects, and 404s on refresh. Our deploy troubleshooting guide covers the usual problems.

Then connect your domain. Buy it from any registrar, point it at your host following the host's instructions, and make sure HTTPS works on both the bare domain and www. Update your auth provider's redirect URLs to the new domain.

Sunday morning: payments or a waitlist

If you're charging from day one, the simplest path is a hosted checkout: Stripe Payment Links or Stripe Checkout. You don't handle card details, and you can test everything in Stripe's test mode with test cards before going live. If your app unlocks features after payment, grant access from a verified webhook, not from the thank-you page.

Not ready to charge? Put up a waitlist with a clear promise ("Early access in November, founding price locked in") and collect emails with a newsletter tool.

Sunday afternoon: the launch checklist

Before you tell anyone, run through this list:

  • Sign up, log in, log out, and reset a password on your phone and your laptop.
  • Complete the core action and a test payment end to end.
  • Check that your page titles, descriptions, and social preview image look right when you paste the link into a message.
  • Add basic analytics so you can see where people drop off.
  • Add a contact email and short Terms and Privacy pages.
  • Submit your sitemap to Google Search Console.

Sunday evening: announce it

Write one short post that explains the problem, shows the product in a screenshot or 30-second clip, and gives one link. Share it where your users already are: X, a relevant subreddit, a Discord, or a Product Hunt launch later in the week. Reply to every comment. Your first ten users will tell you what version two should be.

What usually goes wrong

When launches slip, it's rarely the idea. It's the plumbing: DNS, auth redirects, environment variables, webhooks, or an AI assistant stuck in a loop on the last bug. If that's where you are, you're closer than it feels.
